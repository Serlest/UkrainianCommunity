Real-helper/in-memory-SDK probe подтвердил отсутствие передачи1ошибки наружу; это не реальный cloud/production сбой. Нужны отдельно разрешённые local helper/tests fix и проверка; запрос пользователю отправлен, ответа пока нет. Android56 содержит только inert contract/tests, все deletion endpoints закрыты. Не включать dispatch/UI до разрешения gate, не читать чужие notification inbox для подмены доказательства. Полные пути/хэши/границы — верх overnight checkpoint; cloud/credential pause остаётся.

2026-09-02, baseline `c9c2a69`. Только локальное чтение кода и emulators. Никаких Rules edits/deploy, IAM/App Check changes или production read/write. Исторический checkpoint Storage ENFORCED / Firestore и Auth monitoring не перепроверялся в cloud и не является текущим подтверждением.

## Notifications: Android путь целиком

Системное разрешение уведомлений → пользовательский opt-in → текущий installation/token → запись с ролью и TOTP → trigger/recipient scope → FCM platform payload → foreground/background presentation → auth/startup gate → проверенный route → detail read → read/archive/delete/badge sync. На logout/account switch удалить только текущую регистрацию; race проверять по захваченному uid. При отказе permission inbox остаётся отдельной функцией. Локальные event reminders пересоздавать при изменении регистрации/даты/отмене/параметров/аккаунта. API 33+ runtime POST_NOTIFICATIONS, channels и exact-alarm/Doze-поведение требуют Android-specific реализации, не разрешения сверх необходимости.
