Карточки новостей/событий/организаций проверяются здесь как вложенные переходы: загрузка правильного id, действия сохранения/подписки/регистрации, возврат, недоступный материал. Полный аудит редакторов, комментариев, рекомендаций, модерации и публичных каталогов остаётся в пунктах 5–10.

## Роли

Одинаковые личные разделы у владельца приложения, администратора приложения, владельца/администратора/редактора организации и обычного пользователя. Повышенная роль не меняет userId в запросах личной коллекции. Предупреждённый активный пользователь сохраняет доступ. Гость, заблокированный/отключённый аккаунт не получают эти маршруты. Гостю показывается понятный экран со входом/созданием аккаунта; ожидание загрузки личных данных для него недопустимо. Смена пользователя/прав сбрасывает стек и личные данные; поздние ответы предыдущей сессии не должны применяться.

Проверка прав: ProfileAccessPolicy, PermissionService, guarded profile routes, Firestore Rules, callable registration mutation. У владельца платформы есть серверные административные права на некоторые общие коллекции; личные экраны всё равно запрашивают только его записи.

## Обязательные состояния

Для каждого списка: первая загрузка, заполненный и пустой ответ, пустой поиск, фильтр, обновление с сохранением строк, ошибка/повтор, недоступный материал, повторное нажатие, пагинация (где есть), изменение из карточки, возврат, повторное открытие, смена аккаунта и поздний ответ. Для удаления: отмена, успех, ошибка и сохранность основного объекта. Визуал: uk/de, light/dark, обычный/увеличенный шрифт, поиск/клавиатура, контекстные меню/подтверждения.

## Границы доказательств

Тестовые данные симулятора и эмулятор Rules не заменяют реальные действия двух пользователей на production. Разрушительные сценарии выполняются только на изолированных данных. Изменения кода, развёртывание сервера, TestFlight и приёмка на iPhone фиксируются отдельно.
