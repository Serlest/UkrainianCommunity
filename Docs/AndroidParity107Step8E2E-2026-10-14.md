## Что ещё нужно для закрытия шага 8

1. На доступном личном физическом Android проверить вход существующего пользователя и привилегированного аккаунта, обновление юридических документов, реальное письмо восстановления, Google/passkey где они настроены, модерацию и редактор по ролям. Тестовое административное подтверждение email не заменяет эти сценарии.
2. Проверить реальную регистрацию токена и доставку FCM, открытие уведомлений в холодном и тёплом запуске, отказ в разрешении и удаление регистрации. Локальные push-тесты и развертывание callable подтверждают только части цепочки.
3. На свежем API 37 запустить авторизованные корневые экраны и проверить порядок озвучивания и действия TalkBack, фокус и готовность сетевого контента; затем повторить на физическом устройстве. Первичная проверка API 37 теперь пройдена только для экрана входа и теста синтетических корневых экранов. Старый AVD с `RUNNING_LOCKED` оставлен без изменений.
4. Для баннеров использовать доступное тестовое изображение и проверить серверные квитанции показа/клика, дедупликацию и отчёт владельца. Сейчас подтверждено только согласие и его отзыв.
5. Пройти реальные права владельца/редактора и закрыть ручные приёмки шагов 3–6. Текущие синтетические аккаунты проверяли обычного пользователя и не доказывают поведение MFA, owner UI или публикацию.

После этих проверок обновить отчёт, закрыть шаг 8 отдельным подтверждением и только затем обсуждать шаг 9.
