# Незавершённые регистрации: локальный пакет очистки

Статус: реализовано локально, production не изменён. Новый iOS-билд для серверного механизма не требуется. Пользователь 2026-09-03 подтвердил границу «не раньше 30 дней» и обязательное исключение всех аккаунтов с подтверждённым email, независимо от давности входа. Это не разрешение на deploy/apply. Дополнительный защитный интервал без входа/refresh — 7 дней.

## Политика

- Только email/password: email не подтверждён, аккаунту не менее 30 дней, входа/обновления сессии не было минимум 7 дней.
- Исключены подтверждённые аккаунты, другие/связанные провайдеры, анонимные аккаунты, MFA, custom claims, отключённые аккаунты, Auth phone/photo и некорректные даты.
- Firestore-профиль должен отсутствовать либо соответствовать неизменённой начальной регистрации: обычная роль, активный статус, нет блокировки, предупреждений и membership; `createdAt == updatedAt` с точностью Timestamp; нет неизвестных полей. Это не удаление всех пользователей с неподтверждённой почтой.
- Любые найденные связанные данные исключают аккаунт: публичный профиль, аналитическая активность, дочерние коллекции пользователя (включая данные без родительского документа), организация/заявка/роль, авторство, комментарии, регистрации, likes, feedback, DSA/legal/audit/system logs и уведомления по существующему реестру accountDeletionReferencePolicies.
- Любой файл под `profileImages/{uid}/` или `users/{uid}/` также исключает аккаунт. Медиа и связанные материалы этот механизм не удаляет.
- Ошибка запроса, доступа или индекса — остановка, не доказательство отсутствия данных.

## Выполнение

Новая экспортируемая функция: `cleanupUnverifiedAccounts`. Подготовлен ежедневный запуск в 04:43 Europe/Vienna; он пока не развёрнут.

`UNVERIFIED_ACCOUNT_RETENTION_MODE`:

- отсутствует / `off`: никаких чтений пользователей и удалений;
- `report`: только чтение, сводные счётчики; никакой записи курсора, lease, задания или удаления;
- `apply`: защищённое выполнение; устанавливается только отдельным согласованным production-пакетом.

Неизвестное значение режима вызывает ошибку. Не добавлены клиентские callable, изменения Firestore/Storage Rules или клиентские права.

За один запуск просматриваются не более 500 Auth-записей, страницы по 100, мягкое ограничение работы — 4 минуты. Для apply сохраняется курсор завершённой страницы; прерванная страница будет перечитана. Read-only preflight продолжает с `continuationToken`; `scanComplete=false` нельзя выдавать за полный аудит. Обычный запланированный report начинает с первой страницы; при базе более 500 аккаунтов полный preflight требует продолжений.

### Порядок удаления

1. Транзакционный lease на запуск в `unverifiedAccountRetentionControl/daily`; срок 15 минут длиннее timeout функции 540 секунд. Потерявший lease worker не может менять журнал/профиль.
2. Повторная проверка Auth, профиля и связей. Транзакционное создание задания в `unverifiedAccountDeletionJobs/{uid}` со сравнением точной версии профиля.
3. Ещё одна проверка Auth непосредственно перед удалением. Сначала удаляется Auth, затем проверяется его отсутствие.
4. Повторная проверка связанных данных; удаляется только прежний корневой `users/{uid}` с транзакционной проверкой версии. `recursiveDelete` не используется.
5. Проверка отсутствия Auth и профиля, статус `completed`.

Прерванные `authDeletePending`/`authDeleted` задания читаются раньше новых кандидатов. Неопределённый ответ Auth оставляет профиль и задание для повторной проверки. Воссозданный Auth или изменившиеся после удаления данные дают `manualReview`; они не стираются. Завершённые/отменённые технические квитанции удаляются не ранее чем через 90 дней в режиме apply. Незавершённые/manualReview записи автоматически не удаляются.

Журнал содержит UID, SHA-256 fingerprint состояния, точную версию документа, статусы и даты — без email, паролей, секретов MFA или копии профиля. Он закрыт для клиентов существующим default-deny. Обычный лог содержит агрегаты, не UID/email и не курсор. Профильное удаление запускает существующий `trackDeletedUserAnalyticsAggregate`; отдельная логика агрегатов не изменялась.

## Обязательные условия перед production

1. Перед включением сверить согласованную границу 30 дней, защитный интервал 7 дней неактивности и отражение срока незавершённой регистрации в privacy/регистрационных текстах. Публичные документы этим пакетом не менялись.
2. Выполнить отдельный **read-only** preflight на реальных данных: полный обход, точный закрытый список кандидатов, причины исключений, доступ к Auth/Firestore/Storage, все используемые collection-group indexes. Эмулятор не доказывает наличие production indexes или IAM.
3. Проверить действующие резервные копии и восстановление Auth отдельно от Firestore: Firestore backup/PITR не является резервной копией Firebase Authentication. Этот пакет не создаёт экспорт паролей и не обещает восстановить удалённую Auth-запись из Firestore.
4. Разрешить остаточную гонку, описанную ниже, **до** разрешения apply. Проверить совместимость IAM/runtime и существующих алертов, развернуть только новую функцию в `off`/`report`, сделать read-back. Сам деплой не является разрешением на удаление исторических аккаунтов.
5. После отдельного разрешения на apply — ограниченный проверенный старт, read-back результатов, проверка повторного запуска и алертов. При остановке выключить режим; уже удалённый Auth этим переключением не восстанавливается. Проверить и закрыть оставшиеся задания отдельно.

### Существенное ограничение Firebase

Auth `getUser` и `deleteUser` не образуют атомарного «удалить, только если email всё ещё не подтверждён». Пользователь может подтвердить почту в очень коротком промежутке между последней проверкой и запросом удаления. Аналогично между отдельными сервисами нет общей транзакции, блокирующей все новые связи. Повторные проверки, quiet period, lease и журнал уменьшают риск и защищают профиль от перезаписи, **но не дают абсолютной гарантии сохранения Auth при одновременном подтверждении**.

Поэтому apply по умолчанию выключен. Если требуется абсолютная гарантия, его нельзя включать только на основании зелёных тестов: нужна отдельно спроектированная согласованная блокировка/финализация регистрации либо сохранение режима report/manual review. API: [Identity Platform accounts.delete](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v1/accounts/delete), [Firebase Admin user management](https://firebase.google.com/docs/auth/admin/manage-users).
