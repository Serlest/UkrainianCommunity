# UAC 1.0.2 (68): production, TestFlight и App Review

Состояние на 4 сентября 2026 года, 18:00 по Вене: UAC 1.0.2 (68) отправлена на App Review по прямому разрешению пользователя. Apple подтвердила WAITING_FOR_REVIEW и у заявки, и у версии. Выбрана сборка 68, режим публикации MANUAL сохранён. Совместимое обновление production завершено и проверено, сборка VALID в TestFlight. Публичный выпуск не выполнялся; одобрение Apple само по себе его не запустит.

## Что уже работает на сервере

- Обновлены ровно 16 существующих функций и добавлены 7 новых. Всего 121 функция ACTIVE. У остальных 98 функций время развёртывания не изменилось.
- Действующие Firestore и Storage Rules побайтово совпали с отдельным проверенным iOS-пакетом. Соседние изменения Android не развёрнуты.
- Для каждой из 23 функций скачан именно её развёрнутый исходный архив: все 108 файлов Functions совпали с проверенным пакетом. Сохранены исходные архивы прежних 16 функций и прежние Rules для восстановления.
- Роли пользователей и требования двухэтапной защиты сохранены. Storage App Check остаётся ENFORCED, Firestore/Auth — в прежнем режиме мониторинга. Служебные аккаунты функций сохранены.
- Новые маршруты организации и фото выключены для всех: `mode=shadow`, `commandsEnabled=false`. Уборка новых и старых фотографий выключена; новое расписание фото приостановлено. Прежние расписания сохранены.

Серверные исправления существующих операций уже развёрнуты. Клиентские исправления из [заключительного аудита](IOSFinalReleaseAudit-2026-09-04.md) требуют установки сборки 68. Новый сценарий замены фото дополнительно требует поэтапного включения серверной настройки.

## Что действительно проверено на production

Использован существующий обычный демонстрационный аккаунт для Apple: нормальный вход по паролю, без MFA, изменения роли и создания новых аккаунтов. Создана одна временная архивная организация, недоступная в публичном каталоге. Подача заявки, публикация контента и отправка уведомлений не выполнялись.

Face ID и доставка APNs на физический телефон остаются непроверенными согласно выбранному пользователем режиму работы на Simulator.

## Сборка и загрузка

- Номер в основном проекте увеличен с 67 до 68; версия остаётся 1.0.2, bundle ID — `at.serlest.UkrainianCommunity`, Firebase — production.
- Подписанный архив собран успешно. `codesign --verify --deep --strict` прошёл, `ITSAppUsesNonExemptEncryption=false`. Тестовые адаптеры и временная облачная конфигурация отсутствуют в символах Release.
- Проверены контрольные суммы всех 674 файлов пакета: по сравнению с предыдущим аудитом изменён только номер сборки в project.pbxproj. Документы отчётов учитываются отдельно. Валидатор конфигурации build 68 и `git diff --check` прошли.
- Загрузка через API-ключ остановилась на облачной подписи, до отправки пакета. Проверено, что build 68 ещё отсутствует в Apple; использована существующая сессия Xcode. Повтор завершился с кодом 0, `Upload succeeded`, `Uploaded package is processing`, `EXPORT SUCCEEDED`.
- Apple предупредил об отсутствующих dSYM для пяти встроенных библиотек: FirebaseFirestoreInternal, absl, grpc, grpcpp, openssl_grpc. dSYM самого приложения соответствует UUID бинарного файла. Предупреждения сохранены: они ограничивают расшифровку стеков этих библиотек и не были объявлены исправленными.

В Apple отдельно прочитан объект загрузки: COMPLETE, список ошибок пуст; связанная сборка — 68 / VALID. Проверены инструкции UK и DE, `usesNonExemptEncryption=false`. При последующей отправке на App Review выбранная сборка обновлена с 67 на 68; связь подтверждена чтением API.

## Отправка на App Review

- Apple приняла заявку 4 сентября 2026 в 16:00:31 UTC (18:00 по Вене). ID: `32c166a9-f4be-413f-b1cd-cfb6c70f1ccd`.
- Повторное чтение подтвердило `WAITING_FOR_REVIEW`, версию `1.0.2`, сборку `68` и `releaseType=MANUAL`. В заявке ровно один элемент — эта версия приложения.
- Украинский и немецкий тексты «Что нового» и примечания App Review обновлены по подготовленному предложению и прочитаны обратно с точным совпадением. Реквизиты обычного демонстрационного аккаунта и контактные поля сохранены без изменений.
- Отправка выполнена через App Store Connect API; вход в браузере для неё не потребовался. Анкета App Privacy не изменялась и не объявляется проверенной.

## Незакрытые шаги

1. Дождаться решения Apple по этой заявке. При одобрении публикация остаётся отдельным ручным действием.
2. До публичного выпуска сверить действующую анкету App Privacy с поведением приложения. Имеющийся снимок общего раздела не подтверждает все ответы; API-доступ не предоставляет их.
3. После проверки новой сборки включать новые маршруты сначала для контрольных аккаунтов и отдельных действий. Общую уборку старых фото не включать одновременно с первым запуском.

## Особенности развёртывания и восстановление

Первый вызов Firebase CLI сообщил HTTP 409 для release Rules. Вместо повторной публикации сначала прочитаны действующие правила: оба файла уже совпадали с нужным кандидатом, функции ещё не менялись. Затем отдельно развёрнуты только 23 функции. Итог подтверждён чтением API и исходных архивов, а не одним кодом завершения CLI.

При проблеме нового маршрута первый шаг — выключить `mode`/`commandsEnabled`, сохранив старые API, квитанции операций и файлы. Для более глубокого восстановления сохранены прежние Rules и точные исходные архивы функций. Возвращать прежний код следует адресно по затронутой функции с сохранением её региона, окружения и служебного аккаунта; новые функции и квитанции не удалять массово. Текущие выключенные настройки уже соответствуют начальному безопасному режиму.
