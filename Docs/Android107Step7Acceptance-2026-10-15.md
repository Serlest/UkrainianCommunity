## Подпись, внешние способы входа и ссылки

- Play Console по-прежнему показывает Build **86 (1.1)** в Internal и Closed Test; нового кандидата не загружали. Подтверждены действующий Play App Signing SHA-256 `53:90:B5:6A:03:3C:A3:AC:83:63:E3:2F:56:EF:FB:D1:CC:4E:F5:71:0C:19:79:F2:36:21:7C:94:88:77:5C:A9` и upload SHA-256 `C7:F9:7B:B4:BE:68:C8:5E:AD:95:A6:7D:29:35:67:08:87:4C:36:97:A6:EA:69:45:3F:78:37:D8:3F:7F:EF:BE`; оба уже записаны в production Firebase.
- В production Firebase Android **нет SHA-1**, а скачанная конфигурация не содержит Android OAuth-клиента Google. Play App Signing SHA-1 из публичного сертификата Play: `19:5C:20:74:D2:AE:61:33:21:84:B3:71:50:24:8B:CA:DF:9C:CB:A5`; upload SHA-1 в Play: `A7:B6:47:4D:70:8E:F3:E5:72:4B:AD:25:F0:58:6D:D3:02:B1:AE:35`. Это настройка для проверки перед Google-входом в Play-сборке, а не выполненная production-правка.
- Staging Firebase Android имеет SHA-1 и Android OAuth-клиент; тестовый APK показывает кнопку Google. Его повторный Google-вход после offline вернул ошибку и с временным App Check debug token; на эмуляторе отсутствует Google-аккаунт. Причину успешностью клиента не подменять.
- Живой staging `assetlinks.json`: HTTP 200, JSON, `delegate_permission/common.get_login_creds` для staging package и SHA-256 установленного debug APK. Живой production `assetlinks.json`: HTTP 200, JSON, правильные два SHA-256 и **только** `delegate_permission/common.handle_all_urls`. Перед включением production passkey добавить `delegate_permission/common.get_login_creds`, сохранив действующую связь ссылок, затем прочитать опубликованный файл и пройти вход на Play-доставленной сборке.
- Обычная staging debug-сборка по умолчанию скрывает Apple/passkey; отдельный диагностический APK собран с обоими флагами `true`, успешно запущен и использован только на эмуляторе. Для Play кандидатных флагов и подписей нужен отдельный шаг 8.

## Ворота, которые остались до закрытия шага 7

1. На staging синхронизировать Storage Rules, 18 составных индексов, отличающиеся field overrides и нужные отсутствующие callable, затем получить READY/ACTIVE/live Rules read-back и повторить затронутые Android UI → backend → server read-back сценарии на одноразовых данных. Этот read-only аудит **не разворачивал** облачные изменения.
2. На физическом Android с разрешённой отладкой либо через Play Internal после отдельного разрешения: войти существующим тестовым аккаунтом, подтвердить реальные письма, TOTP, Google/Apple/passkey при включённых конфигурациях, системный выбор и удаление реального фото, FCM permission/delivery/tap/revoke, TalkBack DE/UK и offline → online recovery. Корпоративный Samsung для этого не подходит без решения IT.
3. До кандидата Play решить production App Check Android Play Integrity и Google OAuth SHA-1, дополнить production Digital Asset Links для passkey, затем проверить эти настройки с Play-подписью. Production Auth/данные не менялись.

**Статус:** шаг 7 выполнен максимально в read-only/эмуляторной части, но **не завершён**. Причина не только отсутствие физического устройства: выявлены проверяемые расхождения staging и production-конфигурации. Шаг 8 не начат и требует отдельного разрешения после закрытия ворот шага 7.
