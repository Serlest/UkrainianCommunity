# Заключительная проверка iOS перед новым обновлением

Текущее продолжение: [production и сборка 1.0.2 (68)](Build68Release-2026-09-04.md). Приведённые ниже результаты относятся к этапу до этого развёртывания.

Локальный аудит и заключительная регрессия завершены 4 сентября 2026 года. Дополнительные дефекты исправлены, неуспешные проверки разобраны и повторены. Этот документ содержит итоговые результаты вместо прежних промежуточных чисел. Пользователь поручил работать на Simulator без подключения iPhone; рабочий аккаунт и коды двухэтапной проверки не потребовались. Production, TestFlight и публичная версия не изменены. Облачный этап впоследствии завершён: см. [актуальный отчёт тестового Firebase](IOSCloudValidation-2026-09-04.md). До выпуска остаются развёртывание в production и App Store проверки.

## Что изменится для пользователя после выпуска

| Раздел | Что подготовлено | Что это означает |
|---|---|---|
| Права доступа | Серверные решения и команды для редактирования организации и фотографий, причины отказов, включение по действиям и тестовым аккаунтам, выключение маршрута | После установки обновления выбранные действия можно переключать на сервере без нового iOS-релиза. Это не перенос всех разрешений приложения: старые клиенты остаются под действующими Rules, системные разрешения iOS по-прежнему контролирует iOS |
| Двухэтапная защита | Нынешние требования сохранены | Дополнительных запросов кода не добавлено. Passkey и отмена существующей двухэтапной защиты в этот пакет не входят |
| Напоминания | Очередь привязана к аккаунту, изменения выполняются последовательно | Поздний ответ предыдущего аккаунта не должен вернуть его напоминания после переключения или выхода |
| Фото и редактирование | Замена с проверкой прежней версии, сохранение черновика при конфликте, повтор после обновления записи, обработка неизвестного результата загрузки | Два редактора не перетирают изменения друг друга; замена не увеличивает счётчик фотографий. Неполученный ответ сервера не означает, что загруженное фото нужно сразу удалить |
| Отмена события | Ограничены поля, разрешённые при отмене; серверное завершение проводится через повторяемую задачу | Отмена не должна одновременно незаметно менять другие поля; частичный сбой серверной обработки можно завершить повторно |
| Аналитика | Согласие связано с версией нужного документа; сохраняются подтверждения; поздние запросы не отменяют новый выбор и не восстанавливают удалённый профиль | Сервер не должен записывать старую версию согласия из-за неверного соответствия документов или принимать запоздавшее согласие после отзыва |
| Face ID | Разблокировка привязана к аккаунту, устаревший результат игнорируется, доступна отсрочка повторной блокировки 60 секунд, системный код устройства служит запасным способом | Быстрый переход в другое приложение может обходиться без повторного Face ID при выбранной отсрочке; разблокировка одного аккаунта не разблокирует другой |
| Юридический раздел | Постраничная полная история и экспорт согласий; проверка на 501 записи | Исправлена полнота служебной истории. Юридические тексты не переписаны и юридическое заключение этим аудитом не выдаётся |

Клиентские изменения заработают после установки новой сборки. Серверные исправления и новые маршруты требуют отдельного развёртывания; до него действующая система продолжает работать как сейчас. Отключение нового маршрута помогает при проблеме с ним, но не может автоматически исправить любой дефект старой версии приложения.

## Что дополнительно найдено и исправлено

| Проблема | Последствие | Исправление |
|---|---|---|
| После конфликта фотографий форма сохраняла черновик, но не позволяла обновить исходную версию внутри редактора | Повтор снова отклонялся; закрытие формы теряло выбранное фото и подпись | Кнопка обновления получает актуальную запись и оставляет черновик; пользователь повторно подтверждает сохранение. Отдельно проверены отсутствие сети и удалённая фотография |
| Новая серверная загрузка фото не требовала App Check | Перенос загрузки из Storage мог убрать уже действующую автоматическую проверку подлинности приложения | Проверка включена только у нового `saveOrganizationPhoto`. Никаких новых кодов TOTP; прежние API не ужесточены |
| Аккаунт мог исчезнуть или быть деактивирован после первоначальной проверки согласия | Запоздавшее согласие могло восстановить служебные записи после удаления | Актуальный профиль проверяется внутри транзакции; поздний grant отклоняется, withdrawal после удаления ничего не создаёт |

| Устаревшая транзитивная зависимость `qs` | Предупреждения security audit | `qs 6.16.0`, две совместимые копии `gaxios 7.3.1`, без понижения Firebase SDK |
| Тест фильтров ожидал ранее намеренно удалённую кнопку | Ложная ошибка полной UI-регрессии | Тест приведён к интерфейсу после `bf5ab31`; проверка порядка, выбора и снятия фильтров сохранена |

При просмотре снимков iPad дополнительно обнаружено обрезание названий категорий при максимальном Dynamic Type, хотя проверка логотипа проходила. Исправлен общий выбор категорий/типа страницы/услуг: одна колонка при accessibility-размере, перенос полного текста, масштабируемое место под значок. Добавлен UI-сценарий ширины и отдельных строк. Также тестовый помощник вкладок теперь распознаёт верхние кнопки iPad; подтверждённая ошибка была в ожидании контейнера iPhone TabBar.

## Совместимость и комплект для сервера

Действующие Firestore и Storage Rules повторно прочитаны из production и побайтово совпали с HEAD. Отдельный пакет содержит только ограничение полей отмены события и запрет перезаписи существующего файла галереи. Соседнее расширение push-регистрации на Android не включено. Основной файл Rules с Android-работой не перезаписывается узким вариантом.

Старые API, роли, форматы и требования TOTP сохранены. Новые команды выключены по умолчанию. Права повторно проверяются при записи; ответы и черновики привязаны к аккаунту. Нынешние версии клиента продолжают использовать прежний маршрут. Старые прямые пути галереи по-прежнему допускают разрешённому редактору удаление и создание: весь legacy Storage не объявляется неизменяемым. Новые `photoVersions` доступны для записи и удаления только серверу.

В `release-audit/server-candidate/` подготовлен отдельный пакет: 23 экспортируемые функции, 34 исходных модуля зависимостей плюс узкий entrypoint, Rules, lockfile и контрольные суммы. TypeScript этого пакета собрался; проверен точный набор exports. Впоследствии код пакета развёрнут и проверен в отдельном тестовом облаке; в production пакет не развёрнут. См. [облачный отчёт](IOSCloudValidation-2026-09-04.md). `node_modules` локально является ссылкой на проверенные зависимости; перед переносом нужен `npm ci` по сохранённому lockfile.

Порядок выпуска: сначала отдельное облако и проверка Auth/App Check/IAM, затем совместимые серверы в прежнем режиме, новый iOS build, включение действий для тестовых UID, проверка выключения и только после этого расширение аудитории. Старые API и квитанции при откате не удалять. Настройки действий и очистки приведены в `IOSAccessReliability-Finalization-2026-09-04.md`.

## Что не объявляется исправленным или проверенным

- Массовое изменение требований TOTP исключено по решению пользователя. Проверяется сохранение нынешнего поведения, а не устранение исходного F05 посредством усиления MFA.
- Административный поиск пользователей по подстроке всё ещё сканирует коллекцию. Это прежнее ограничение масштабирования F09. Замена на индексированный поиск потребует отдельной схемы и проверки полноты результатов; молча ограничивать поиск первыми записями нельзя.
- `npm audit --omit=dev`: 0 critical/high, 7 moderate из транзитивного advisory `uuid`. Исследованные `gaxios 6.7.1`/`teeny-request 9.0.0` используют `v4`; [advisory](https://github.com/advisories/GHSA-w5hq-g745-h8pq) относится к `v3/v5/v6` с переданным буфером. Это оценка применимости, не утверждение об отсутствии advisory.
- Тестовый облачный этап закрыт отдельным [отчётом](IOSCloudValidation-2026-09-04.md): billing включён с разрешения пользователя, 23 Functions развёрнуты, реальные SDK/права/IAM и выключение новых маршрутов проверены. Аппаратная аттестация не проверена. Новый серверный пакет ещё не развёрнут в production.
- Физические Face ID и APNs не проверены согласно запросу использовать Simulator. Локальные тесты поведения и очереди уведомлений не заменяют эти проверки. Минимальная версия приложения iOS 17 не означает, что тесты запускались на iOS 17.
- API App Store подтвердил отмену `1.0.2`, build 67 и ручную публикацию. Веб-страница App Privacy запросила вход; действующие ответы анкеты не удалось прочитать. Локальный privacy manifest проверен. Публичный выпуск до сверки анкеты не считается готовым согласно release-preflight.
- Архив проверки имеет прежний номер 67 и не подписан/не загружен. Для TestFlight нужен новый уникальный номер, подписанный архив и проверка принятия Apple.

Нельзя обещать отсутствие всех возможных ошибок. Итог определяется подтверждёнными сценариями, сохранёнными отказами, совместимостью и оставшимися внешними шагами.
