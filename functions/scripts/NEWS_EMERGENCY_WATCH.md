# UAC News emergency watch

This is one specialist chat checking **all of Austria every 30 minutes** in Europe/Vienna. It is not an eleventh geographical feed and has no publication target of its own. It routes each useful incident to exactly one of the nine state scopes, or to `austria` only if the actual restriction or warning materially affects more than one state or the whole country. The app already includes `austria` articles in state feeds; a Tirol-only avalanche, mudslide or local train closure must never be tagged `austria` for extra reach.

## What to check on every pass

1. [AT-Alert current official warnings](https://warnungen.at-alert.at/de): read active alerts, issuing authority, area, validity, exact dispatch/update time and instructions. The page embeds `initialAlerts` in its server response; inspect that data as well as the visible unfiltered page before recording a verified zero. A filter showing no alerts is not enough until filters are reset. Tests and exercises are excluded.
2. [ÖBB live traffic notices](https://www.unsereoebb.at/de/verkehrsmeldungen) and [ÖBB traffic newsroom](https://presse-oebb.com/News.aspx?l=deutsch&menueid=27022): identify new unplanned closures, cancellations, replacement buses and routes. For regional operators, check their own live status after identifying the affected state. Planned construction is outside this watch.
3. [ASFINAG current traffic information](https://routenplaner.asfinag.at/?activeTab=traffic-messages&language=de): **run `node functions/scripts/newsAsfinagEvidence.mjs <new-absolute-evidence.json>` on every pass**. The helper follows the official webapp's deployed configuration to its public VAO WFS traffic service and reads the entire `traffic_message_unique` collection, without viewport, zoom, category or date filters. It checks fresh response time, `numberMatched = totalFeatures = numberReturned = actual rows`, unique IDs and validity/publication windows in Europe/Vienna. A capped/malformed/stale response fails, never a verified zero. This is the public map's backend, **not** the separately registered content portal. The map list depends on the visible map bounds; on 30 October it opened over the Mediterranean/North Africa and displayed `Keine Meldungen vorhanden`. Resetting category filters did not restore Austrian bounds. Its empty list cannot prove Austrian coverage.

   Read all current `reviewMessageIds` and their full `notices[].text`, not only the first closure. `review_restriction` includes closures, weather, access restrictions and unknown effects; `review_routine_traffic` is still visible so a significant restriction hidden in an accident/queue is not discarded by type. Explicit planned works and notices outside their validity envelope are separated with reasons; acute hazards in works areas remain for review. A title-only construction record may establish its exclusion but is never full publication evidence. Unknown categories, missing active text or ambiguous/malformed times remain partial. The collection also contains foreign roads and other competent road operators: preserve provider/geometry, determine the affected territory from the actual notice, and never infer Austria-wide scope from the ASFINAG interface. Read daily/weekly schedules inside the text; interval membership alone does not establish that a recurring restriction applies now. A republished `publicationPeriodFrom` does not by itself prove a material change today.

   For a selected significant notice and immediately before live, run `node functions/scripts/newsAsfinagEvidence.mjs --notice '<messageId>' <new-absolute-detail.json>`. It reads the official ASFINAG `GeoFeatureDetails` service, verifies the returned ID, provider, full text, service-level success and current validity. HTTP 200 with `HAMM`/`PARSE`, removal, mismatched IDs or absent text is not active confirmation. Retain the actual `sourceURL` read (the ASFINAG detail endpoint), request method and feature ID as evidence; do not pretend the unread map shell supplied the details or invent an incident permalink. The existing one-source/date/territory/illustration/dry-run/lock/read-back gates still apply. A removed/expired record is not proof that the road physically reopened. If the public service changes or cannot be exhausted, record partial; do not substitute a list zero. The separate [real-time data portal](https://contentportal.asfinag.at/) requires registration and is not configured by this helper.
4. [GeoSphere current weather warnings](https://www.geosphere.at/de/karten/wetterprognose) and [current earthquakes map/list](https://www.geosphere.at/de/karten/aktuelle-erdbeben): focus on actionable severe impact, not routine forecasts or harmless tremors. The weather map may render only `Loading`; check GeoSphere's [documented official warning API](https://openapi.hub.geosphere.at/warnapi/v1/) at `https://warnungen.zamg.at/wsapp/api/getWarnstatus` for the nationwide live warning FeatureCollection. Treat a valid empty `features` array as a checked warning zero, and any API/schema failure as partial. Check the affected municipality/state and any authority instructions directly. For earthquakes run `node functions/scripts/newsEarthquakeEvidence.mjs`: it reads the official map’s `https://www.geosphere.at/data/earthquakes` JSON service and checks the actual rows. The `/erdbeben-karten-und-listen` child is explanatory text, not the current event table. The API uses UTC without a timezone suffix: convert to Europe/Vienna; a late UTC event may be today locally. Read `officialPressText` for consequences. Event time alone is not a news publication/update date. An empty/malformed API response is partial, not verified zero. Harmless weak tremors without impact/instructions are not published.
5. In snow season, use [lawinen.at](https://lawinen.at/) to navigate to the issuing state avalanche service; check its current bulletin and any state warning-center notice. A routine daily risk level without a material new danger or practical restriction is not a news item. An avalanche incident matters if it causes an active road/rail closure, evacuation, access restriction or other confirmed practical impact.

A directly read publication from an approved professional newspaper can also establish a useful warning. Use the source URL where it was read and attribute the report. Do not require a second news source or an additional official press release. The current active restriction, today's publication/update date, affected territory and practical instructions must be established from the opened material itself.

### Reading avalanche services

The official pages embed a JavaScript bulletin or blog. An initial `...`, browser-compatibility fallback or generic danger-level legend is not the final result. Read the rendered iframe after it finishes loading; follow the iframe or blog URL actually exposed by the official state page. Do not substitute the obsolete `/simple/de.html` fallback (which returned 404 on 16 October 2026) for the service itself.

During the off-season, check the state service's explicit end-of-daily-report notice **and** freshly open its linked blog with the correct state selected, all categories/years and no search filter. Record the newest entry and any current exceptional warning. A current page date beside a legend does not establish a daily bulletin. A verified seasonal pause plus a successfully read current blog is a completed off-season check, not a failed daily report; it does not establish that the mountains are safe. A missing/unreadable blog remains partial. Do not carry an old seasonal observation forward without checking for new notices or resumed reports.

Verified navigation on 16 October 2026: Vorarlberg's official page links to `lawinen-warnung.eu` bulletin/blog for `AT-08`; Salzburg's page embeds the same service for `AT-05`. Tirol uses `lawinen.report` for `AT-07`; Kärnten's official blog overview is `https://lawinenwarndienst.ktn.gv.at/blog/posts` and embeds `lawinen.report` for `AT-02`. Use the links actually present on the state page if they change. Check all seven issuing state services before claiming nationwide avalanche coverage; one rendered service and six HTTP responses are partial. Keep past closed reports unchanged; record newly obtained evidence in a separate report or amendment.

## Editorial decision

- **User rule, 16 October 2026:** one directly read official structure/operator notice or approved professional editorial article is sufficient. No second independent confirmation is required. Link to the actual source where it was read. For an ASFINAG live entry, the checked live-map/list URL is acceptable; no separate permanent event link is required. Use manifest `sourcePolicy: "asfinag_official_notice"`, review `evidenceMode: "official"`, `primaryPageKind: "live_notice_list"` (or `"article_or_notice"`), `activeNoticeConfirmed: true` and concrete `noticeEvidence`; recheck activity within ten minutes of the gate. A readable current entry is required, not just a map shell. Preserve today's source date, reader action, territory, deduplication, illustration, dry run, locks and production read-back.
- First check whether the incident is **still active** and its direct source notice/article or material update is dated today in Europe/Vienna, with clear practical effect and a reader action. Exact source hours and minutes are optional; never invent them. Reopen the chosen live source immediately before publication. A direct old notice whose listing disappeared is insufficient. Finished incidents receive no retrospective article just to fill a feed.
- Scope is based on the affected people or route, not the location of a media outlet or the reach of the operator. One affected state means `regionScope=federalState` with that state. Cross-state/national means `regionScope=austria` only when the primary source and practical effect prove it. Do not duplicate the same incident in both scopes. Check prior state decisions and live production IDs before creating content.
- Reject criminal/accident narratives, blame, casualties, party arguments, war updates, rumors, isolated minor delays and routine danger maps. Safety instructions and service restrictions may be reported without those details.
- For a qualifying item follow `NEWS_SCOPE_COORDINATION.md`: one directly opened approved official notice or editorial article dated today; UAC's actual publication time in `publishedAt`; original factual Ukrainian and German full texts with the actual found `sourceURL`; newly generated photorealistic thematic cover, labeled illustration if needed; editorial gate, dry-run, shared locks, live publication, production read-back and terminal regional decision. The emergency run ID is accepted by `newsScopeDecisions.mjs` and does not close a territorial batch.
- If another chat is editing the same event or holds the publication lock, do not start a duplicate write or retry queue. Report the pass partial and recheck fresh status at the next scheduled pass. A partial pass is never represented as a clean zero.
- For a material change to an already published warning, use the controlled existing-record amendment process in `NEWS_SCOPE_COORDINATION.md`, including dry run, owned locks, conditional write and production read-back. Check `<root>/amendments/<contentId>.json` for the latest verified manifest before comparing production. Correct a now-ended restriction in place; do not create a new retrospective article or duplicate URL. The ordinary create-only publisher's semantic conflict is not a reason to leave a confirmed stale active warning indefinitely.
- Rebuild each report's `activeIncidents` from that pass's current source reads and final actions. When an incident is updated or amended, reconcile every repeated incident summary in the report to the same source check time, source update time, active-state result and `amended_existing`/unchanged decision. Never carry a prior pass's incident summary forward as if it were current; keep any historical baseline clearly separate.

Stay silent after an uneventful complete pass. Tell the user only about a published urgent item, a material miss or a persistent source/technical failure. The quality-monitor chat audits this watch after completion; it does not act as a parallel emergency publisher.

ASFINAG shared live-list identity: for each newly published notice set manifest and review `sourceNoticeId` to the exact verified `messageId`, and include that ID in `noticeEvidence`. The publisher binds identity and duplicate claims to the actual source URL plus this notice ID, and production read-back verifies it. Keep `sourceURL` as the real endpoint/list read; never invent query parameters or incident permalinks. Existing publications without this field retain their original ID and manifest; inspect their incident evidence before creating anything and amend the same record for updates. Never add a notice ID to re-identify an old publication.
