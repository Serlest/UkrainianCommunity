# UAC News emergency watch

This is one specialist chat checking **all of Austria every 30 minutes** in Europe/Vienna. It is not an eleventh geographical feed and has no publication target of its own. It routes each useful incident to exactly one of the nine state scopes, or to `austria` only if the actual restriction or warning materially affects more than one state or the whole country. The app already includes `austria` articles in state feeds; a Tirol-only avalanche, mudslide or local train closure must never be tagged `austria` for extra reach.

## What to check on every pass

1. [AT-Alert current official warnings](https://warnungen.at-alert.at/de): read active alerts, issuing authority, area, validity, exact dispatch/update time and instructions. The page embeds `initialAlerts` in its server response; inspect that data as well as the visible unfiltered page before recording a verified zero. A filter showing no alerts is not enough until filters are reset. Tests and exercises are excluded.
2. [ÖBB live traffic notices](https://www.unsereoebb.at/de/verkehrsmeldungen) and [ÖBB traffic newsroom](https://presse-oebb.com/News.aspx?l=deutsch&menueid=27022): identify new unplanned closures, cancellations, replacement buses and routes. For regional operators, check their own live status after identifying the affected state. Planned construction is outside this watch.
3. [ASFINAG current traffic information](https://routenplaner.asfinag.at/?activeTab=traffic-messages&language=de): focus on current unplanned full closures, road access lost from landslides/flooding, dangerous weather and material detours. The public map is dynamic; its shell or HTTP success is not a traffic-data read. Filter out future construction and inspect all current unplanned, safety-relevant results; merely opening a first row does not complete coverage. ASFINAG offers a separate [real-time data portal](https://contentportal.asfinag.at/) with a package for unplanned safety-relevant events, but it requires account registration; do not claim that package is in use until access is configured and a real read succeeds. If the live result list cannot be read or exhausted, record a partial check rather than zero incidents.
4. [GeoSphere current weather warnings](https://www.geosphere.at/de/karten/wetterprognose) and [current earthquakes](https://www.geosphere.at/de/karten/aktuelle-erdbeben/erdbeben-karten-und-listen): focus on actionable severe impact, not routine forecasts or harmless tremors. The weather map may render only `Loading`; check GeoSphere's [documented official warning API](https://openapi.hub.geosphere.at/warnapi/v1/) at `https://warnungen.zamg.at/wsapp/api/getWarnstatus` for the nationwide live warning FeatureCollection. Treat a valid empty `features` array as a checked warning zero, and any API/schema failure as partial. Check the affected municipality/state and any authority instructions directly.
5. In snow season, use [lawinen.at](https://lawinen.at/) to navigate to the issuing state avalanche service; check its current bulletin and any state warning-center notice. A routine daily risk level without a material new danger or practical restriction is not a news item. An avalanche incident matters if it causes an active road/rail closure, evacuation, access restriction or other confirmed practical impact.

If a credible newspaper reports a serious situation missing from these listings, use it as a discovery lead and immediately seek a current direct official notice from the operator, state authority, warning center or infrastructure manager. Never cite a newspaper instead of the primary official source.

## Editorial decision

- Record the local scheduled slot as `emergency-YYYY-MM-DDTHH-00` or `emergency-YYYY-MM-DDTHH-30`. **Finish all source checks before writing** one compact report at `<root>/emergency/reports/<runId>.json`; refuse to overwrite an existing slot. Include `runId`, `checkedAt`, each channel's `checkedAt`, `status` (`complete`, `partial` or `failed`), source URL, active incident URLs, precise scope and rejection/publication reason. If later evidence corrects a saved report, add a separate timestamped amendment with `amends: <runId>.json`; the quality monitor reads the report and its amendments together. If a channel could not be read, name it and mark `partial`; do not equate a working page with complete incident coverage.
- First check whether the incident is **still active**, was new or materially updated in the past 24 hours at a verifiable exact time, has clear practical effect and a reader action. Reopen the live official listing immediately before publication. A direct old notice whose listing disappeared is insufficient. Finished incidents receive no retrospective article just to fill a feed.
- Scope is based on the affected people or route, not the location of a media outlet or the reach of the operator. One affected state means `regionScope=federalState` with that state. Cross-state/national means `regionScope=austria` only when the primary source and practical effect prove it. Do not duplicate the same incident in both scopes. Check prior state decisions and live production IDs before creating content.
- Reject criminal/accident narratives, blame, casualties, party arguments, war updates, rumors, isolated minor delays and routine danger maps. Safety instructions and service restrictions may be reported without those details.
- For a qualifying item follow `NEWS_SCOPE_COORDINATION.md`: direct official notice and independent confirmation; exact timestamp; original factual Ukrainian and German full texts with direct `sourceURL`; newly generated photorealistic thematic cover, labeled illustration if needed; editorial gate, dry-run, shared locks, live publication, production read-back and terminal regional decision. The emergency run ID is accepted by `newsScopeDecisions.mjs` and does not close a territorial batch.
- If another chat is editing the same event or holds the publication lock, do not start a duplicate write or retry queue. Report the pass partial and recheck fresh status at the next scheduled pass. A partial pass is never represented as a clean zero.

Stay silent after an uneventful complete pass. Tell the user only about a published urgent item, a material miss or a persistent source/technical failure. The quality-monitor chat audits this watch after completion; it does not act as a parallel emergency publisher.
