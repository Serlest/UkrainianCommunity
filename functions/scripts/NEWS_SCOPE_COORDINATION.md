# UAC News scope coordination (active)

The active v3 operation uses separate search state for the nine federal states and Austria-wide news without importing the old v2 candidate backlog.

## State layout

- `source-registry.json`: one entry per canonical source URL with its assigned scopes. A source shared by several scopes is fetched once.
- `shared-source-state.json`: fetch observations for those unique sources.
- `scopes/<scope>.json`: separate source cursors and final candidate decisions for each of the ten scopes. All cursors begin as unverified (`null`). No pending editorial candidates are imported or stored here.
- `snapshots/<runId>.json`: immutable results of one shared source scan. `newsScopeBatch.mjs` selects the observations assigned to one scope without making another network request.

`prepareNewsScopes.mjs` previews the layout by default and writes it only with `--write`. It never edits the v2 file. Two historical RIS query URLs with no assigned scope are retained in the registry as inactive review items.

`newsSharedScan.mjs` also previews by default. `--run` performs a real network scan and creates a snapshot for the active coordinator automation. A second scan with the same run ID is refused. Its result is source discovery, not a publication decision or proof of complete source coverage. Article relevance, date, official evidence, and territory still require editorial checks. Salzburg Verkehr's traffic listing is loaded from its official public JSON feed because the HTML page renders article links with JavaScript.

The existing `contentPublishingLocalBridge.mjs` remains the only publisher. It already uses deterministic IDs and Firestore identity locks with atomic create-only writes. News publication must still hold the shared `content-work.lock` while invoking the bridge, then verify the separate production read-back before recording success. Search does not hold that lock.

## One-pass candidate decisions

`newsScopeDecisions.mjs <root> <candidate-batch.json>` previews a scope's decision batch. Once the new system is activated, `--apply` atomically records its technical trace. The input lists every article candidate taken from the current discovery pass and one decision per canonical URL. Only `published` and `rejected` are terminal. A rejected candidate needs a concrete reason. A published candidate needs a matching verified production read-back receipt; the recorder checks its ID, approved status, territory, and `allVerified` result. Missing, duplicate, or pending decisions fail the batch; no editorial queue or draft is created.

Discovery must distinguish article candidates from menus, images, and other non-content links before handing the batch to the recorder. A partial source fetch or uncertain publication is a **partial/failed run**, not a successful empty pass. Keep the affected source cursor unchanged and reconcile any uncertain production write before the next attempt. The scope state contains only final URL decisions and a small run summary; full article text and images are not copied into it. Old v2 pending records remain historical and are never imported into v3. The active nationwide chat has separately been instructed not to process that old backlog.

Major transport disruptions affecting connections across several federal states belong in the `austria` news scope. Publish one nationwide article rather than separate copies for each state; the app includes Austria-wide news in every state's feed. A regional publisher identity used for the write does not change the article's `regionScope` or `federalState`.

The ten territorial chats and coordinator scan run on the schedule below. `manifest.json` must report `active`; if it does not, stop the pass and investigate rather than falling back to v2.

## Editorial gate for a fresh news article

Use `newsPublishingLocalBridge.mjs publish <manifest.json> --review <review.json> --receipt <editorial-receipt.json> <publisher options>` for every v3 news publication, including the dry run. It validates the editorial package immediately before invoking the existing publisher. The gate requires an exact, timezone-aware official publication or material-update time within 24 hours; an official primary site from the approved scope registry; a directly opened article or notice; a directly opened independent source; and a concrete practical effect, audience, and reader action. The manifest's `publishedAt` must equal the verified source event time. A date with no trustworthy time cannot be treated as a precise 24-hour timestamp.

The review JSON records `scope`, `sourceEventAt`, `sourceEventKind`, `primaryURL`, `primaryCheckedAt`, `primaryOpened`, `primaryPageKind`, `officialAuthorityConfirmed`, `independentURL`, `independentCheckedAt`, `independentOpened`, `practicalEffect`, `territoryEvidence`, `affectedPeople`, `readerAction`, `ukDeFactParityConfirmed`, `originalTextConfirmed`, and `excludedTopicsAbsent`. A material update additionally needs `materialChange`. Read the direct article's machine-readable publication and modification metadata when present; convert its exact timestamp and timezone to UTC and compare it with `sourceEventAt` before the dry run. Never substitute a listing timestamp or guess seconds or timezone. Its `image` records `tool: "image_gen"`, `generatedForURL`, `generatedAt`, `prompt`, `sha256`, `photorealisticReviewed`, `topicMatchReviewed`, and `sourceImageCopied: false`. The manifest must use an absolute `imagePath` so the reviewed file is the file sent to the publisher. The gate hashes the actual manifest and cover, checks substantial Ukrainian and German bodies, and writes a bound technical receipt. Image originality, source interpretation, and factual parity still require an actual editorial review; boolean fields alone cannot prove them.

The app's news detail screen displays the direct `sourceURL` as a clickable source section in both language views. The existing publisher writes full `localizations.uk` and `localizations.de` bodies and checks two distinct sources, one official primary and one independent on another site. The v3 candidate decision recorder requires the editorial receipt and a matching production read-back before it can record `published`.

## Scheduled operation (Europe/Vienna)

The coordinator scans the 25 active, unique source listings once at 09:00, 14:00, 19:00 and 22:00. Nine state chats run at 09:20–09:36, 14:20–14:36 and 19:20–19:36, two minutes apart. The Austria-wide chat runs at 09:45, 14:45, 19:45 and 22:45. The chats search and evaluate independently; only a live write takes the shared `content-work.lock`. These are 27 regional and four nationwide editorial passes per day, with no publication quota. The scanner is a separate heartbeat in the coordinator chat, not an eleventh editorial territory. The active ÖBB newsroom and live service listings are required coverage for short-notice rail disruptions; the ÖBB construction page covers planned works and cannot stand in for them. Check each direct ÖBB disruption notice when a relevant service disruption is found.

### Coordinator scan

Check `manifest.json` is `active`. Set `runId` to `news-YYYY-MM-DDTHH` for the current scheduled hour in Europe/Vienna, and run `node functions/scripts/newsSharedScan.mjs <root> <runId> --run` from the UAC repository. If its immutable snapshot already exists, read that snapshot; never overwrite it. Check the actual number of results and errors. A failed source makes the scan partial and must be reported with its source ID. The scanner discovers links only; a successful HTTP response never proves article completeness, freshness or publishability. Do not use the global publication lock for this read-only scan.

### One territorial editorial pass

Read only the assigned scope in the active v3 root. If `lastCandidateBatch.runId` already equals the current wave's run ID, that scope's batch is closed; finish without opening or replacing it. Use the snapshot from the current local-time wave; if absent or older than 90 minutes, report `partial` and do not pretend the pass was complete. `newsScopeBatch.mjs` filters the shared observations to the scope. Inspect likely article links, the direct official notice and an independent site. Navigation links are not article candidates. Registry entries marked `adapter` may be checked manually and included in the decision batch with their exact source ID; `reference` and `excluded` entries cannot become new candidates. A failed shared source leaves its cursor unchanged and makes scope coverage partial, even if other candidates are decided.

For every actual article candidate selected in this pass, decide **published** or **rejected** now. Reject poor, old, duplicate, wrong-scope, party-conflict, crime, murder, unrelated-war, promotional and undated material with a concrete reason. Never store editorial pending/drafts or pull old v2 pending. A zero-publication pass is valid. Do not invent an exact timestamp from a date-only page. The direct primary official page must have a verifiable publication or material-update time within 24 hours; cross-check the specific new claim. Write original full Ukrainian and German copy with matching facts and the direct official `sourceURL`. Generate a new photorealistic thematic image with `image_gen`, copy it into the run's artifact directory, review it, and label it as an illustration if it does not depict the actual place.

Use `newsPublishingLocalBridge.mjs` with manifest, review and editorial receipt for dry-run first. The dry-run must say `status=new`; otherwise reject as duplicate or stop on a concrete conflict. For the live write, acquire both news locks with `runtime.py news-acquire` using this chat's stable thread ID and a unique run ID. If busy, stop as `partial` without a retry loop or a fabricated final decision; a later fresh pass may re-discover the item. Heartbeat a long-held lock. Publish under the exact `uac-<state>-info` organization, or an expressly selected verified regional publisher for nationwide scope. Run `newsProductionReadback.mjs <manifest> <organization-id> <receipt>` immediately after the write. It verifies the production document, both languages, source link, territory, approval and served image. If a write outcome is uncertain, reconcile the deterministic content ID in production before any new attempt. Release only this run's locks in `finally`.

Close the current article candidates with `newsScopeDecisions.mjs <root> <batch.json> --apply` after receipt verification. For a published decision provide `contentId`, absolute `manifestPath` and `editorialReceiptPath`, plus `productionReadback: {verified: true, contentId, receiptPath}`. The receipt must have `allVerified: true`; a boolean alone is insufficient. A rejected decision needs one of the recorder's concrete reason codes. Write exactly one small report per territorial pass at `<root>/reports/<runId>/<scope>.json`, including `scope`, `runId`, `status` (`complete`, `partial`, `blocked` or `failed`), expected and observed source counts, source and coverage errors, decided candidates, publication IDs and concrete reasons for partial or failed coverage. Write the report even when no news qualifies; a closed candidate batch alone does not prove that the source coverage was complete. Do not create a retry queue or editorial drafts. A partial source or uncertain write never advances its source cursor or closes an unresolved candidate as if it were successful.
